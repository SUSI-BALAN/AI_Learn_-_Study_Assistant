# AI Learning & Study Assistant

An offline-first, terminal-only learning assistant built phase by phase from `MASTER_PROMPT.md`.

## Phase 1 setup

Prerequisites: Python 3.10+, Ollama, Qwen 2.5 3B, TinyLlama fallback, and MongoDB.

```powershell
ollama pull qwen2.5:3b
ollama pull tinyllama
Copy-Item .env.example .env
python -m pip install -r requirements.txt
python main.py
```

If Ollama is installed but not running, start it in another terminal with `ollama serve`.
If MongoDB is not installed as a service, start it in another terminal:

```powershell
New-Item -ItemType Directory -Path .\data\mongodb -Force
mongod --dbpath .\data\mongodb --bind_ip 127.0.0.1 --port 27017
```

Available commands: `/help`, `/clear`, and `/exit`.

Run Phase 1 tests:

```powershell
python -m unittest discover -v
```

Phase 2 persists the local student profile and conversations in MongoDB. The app
continues with session-only chat and a warning when MongoDB is unavailable.

Phase 3 can extract normalized, source-aware records from PDF, TXT, Markdown,
DOCX, and PPTX files through `app.rag.loader.load_document`. Indexing and `/add`
remain intentionally deferred to Phases 4 and 5.

Example loader use:

```python
from app.rag.loader import load_document

records = load_document("data/documents/course.pdf")
```

Grounded answer generation, citations in chat, and learning tools belong to later phases.

## Phase 4 local vector search

Phase 4 uses ChromaDB with the local ONNX `all-MiniLM-L6-v2` embedding model.
The model is downloaded once by ChromaDB (about 79 MB) and then works offline.

Place supported study files in `data/documents`, then batch-index them with:

```powershell
python ingest.py
```

The indexing service preserves document IDs, filenames, file types, subjects,
topics, page/slide/section locations, chunk indexes, and chunk text when those
fields are available. `/add`, `/documents`, grounded answers, and displayed
citations remain Phase 5 work.

## Chat routing

Greetings and general questions use the adaptive `prompts/normal_chat.txt` prompt.
Answer length and structure are selected from the current question's intent.
Normal factual answers are generated by the configured Ollama model; no factual
answers are hardcoded. `qwen2.5:3b` is the default primary model and TinyLlama is
used only as a fallback when the primary model is unavailable.
Explicit phrases such as “according to my uploaded notes” use semantic retrieval
and `prompts/rag.txt`. When retrieval finds no qualifying chunks, no document
context is sent to Ollama and the assistant reports insufficient evidence.
